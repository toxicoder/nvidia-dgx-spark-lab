Prerequisites

  • 1–5 DGX Spark nodes, Ubuntu 22.04 or 24.04 (fabric per node count: Choose topology)
  • nvidia-smi works on the node
  • SSH key + sudo from your workstation (operator client)
  • Out-of-band console (IPMI/iDRAC) — heavy Jobs can still wedge SSH if you skip Guard
  • Operator client (the machine that runs Ansible and manage.sh): Ansible ≥ 2.14, kubectl, helm, bazelisk

One command installs and verifies everything (Homebrew, no sudo):

status subcommand reports what is already present; see Shell reference for the full contract.

Safety

Never proceed without inventory ping and OOB access. Do not start kimi / Mode B/C until start-test succeeds.

Step 1 — Topology file (inventory)

The declarative topology ansible/inventory/lab.yaml is the single source of truth for all five configurations — node names/IPs, fabric, switch port map, and which Spark is the orchestrator. Edit it, then render:

Rendering produces the Ansible inventory (ansible/inventory/hosts.ini, gitignored), fabric group vars, per-node netplan, and per-node cloud-init user-data — all from the topology file. Full model: Lab topology.

Day-2 Ansible uses lab-ansible, not the factory ubuntu account. After topology render, create keys and apply identities before ansible ping as lab-ansible:

First-contact SSH is still bootstrap_user (default ubuntu). Details: Lab identities.

fabric: none, one node with role: orchestrator. No high-speed cabling, local NCCL only.

Any node may be the orchestrator — see Choose topology → Pick your orchestrator.

Legacy hand-made inventory

Still prefer a manual hosts.ini? cp ansible/inventory/hosts.ini.example ansible/inventory/hosts.ini and edit it — the classic path still works, it just skips the generated netplan / cloud-init.

Step 2 — cloud-init (physical nodes)

Render early OS / highspeed user-data before or as the first part of bootstrap.

With a lab.yaml in place, user-data is generated per node at ansible/files/generated/cloud-init/user-data-<node>.yaml (all five fabrics). The static examples ansible/cloud-init/example-user-data-1node.yaml / example-user-data-2node.yaml remain for ad-hoc labs. Feed rendered YAML via vendor BMC, or apply manually and reboot.

apply_now=true

Extra-var apply_now=true writes user-data on the node and can reboot it. Inference must already be stopped. Default is render-only.

To import prep from bootstrap: --extra-vars run_cloud_init_prep=true.
